1. EXECUTIVE SUMMARY & KEY FAILURE MODES
================================================================================
The JobHunt platform is an ambitious, feature-rich job aggregation platform 
integrating 10 scraper sources, AI/heuristic ranking, vector search, PostgreSQL 
persistence, and real-time streaming to a React UI.

However, the platform is currently failing to deliver accurate search results 
due to several foundational bugs:
  a) Location Leak: Any job located anywhere in India (Bangalore, Delhi, Mumbai, 
     etc.) receives a 100% location fit score for any specific city search 
     (e.g., Pune), causing out-of-city jobs to dominate curated results.
  b) Silent Date Filter Bypass: If zero jobs match a requested date freshness 
     window (e.g., past 24 hours), the code ignores the filter and returns 
     stale, month-old jobs without notifying the user.
  c) 2-Letter Token Stripping: Direct ATS scrapers (Ashby, Lever, Greenhouse, 
     Phenom) strip all search tokens of length <= 2. Searching for "AI", "ML", 
     "QA", or "Go" strips the tokens to an empty list, which bypasses title 
     filtering and dumps all company postings (HR, Sales, Legal) into the feed.
  d) AI Role Generic Bypass: The role helper contains a clause that marks any 
     generic Software Engineer, Frontend, or Backend role as a valid match 
     when an AI target role is searched.
  e) Substring Skill False Positives: Ranking uses naive substring matching 
     (`s in desc_lower`), causing single-letter skills like "R", "C", and "Go" 
     to match inside words like "transformers", "docker", and "google".
  f) Unbounded Duplicate Growth: The database inserts new rows with random 
     UUIDs on every single search without checking for existing URLs or source 
     IDs, leading to massive database bloat.
  g) Undated Job Immortality: Jobs with missing or unparseable dates return True 
     for date freshness, permanently passing through 24-hour filters.

[BUG-CRIT-005] Unbounded Database Duplication via Random UUID Insertion
  Files:
    - backend/src/services/job_service.py (Lines 321-354)
    - backend/src/repositories/job_repository.py (Lines 10-35)
    - backend/src/models/job.py (Lines 8-48)
  Function: JobService.execute_pipeline(), JobRepository.add_jobs()
  Problem:
    Every search generates a new `search_id` and assigns `id=str(uuid.uuid4())` 
    to each scraped job. It then calls `db.add_all(db_jobs)`. There is NO unique 
    constraint on `Job.url`, and no deduplication against existing database records.
  Impact:
    Running the same search 10 times creates 10 duplicate rows for every single 
    job posting in PostgreSQL. The database bloats uncontrollably, search 
    performance degrades, and `get_latest_background_pool()` returns duplicate rows.
  Fix:
    Generate deterministic primary keys: `id = hashlib.sha256(canonical_url.encode()).hexdigest()`.
    Use PostgreSQL `ON CONFLICT (id) DO UPDATE` or pre-filter existing job URLs.

[BUG-HIGH-001] FreeHire Geographic Fallback Pollutes City Feeds
  File: backend/src/integrations/freehire/client.py (Lines 198-207)
  Function: FreehireClient.search()

[BUG-HIGH-004] Substring Skill Matching Produces False Positives
  File: backend/src/agents/ranking.py (Lines 76-80)
  Function: RankingAgent._score_job()
  Problem:
    Skill match evaluation uses:

  Impact:

[BUG-HIGH-005] Operator Precedence Bug in Skill Scoring
  File: backend/src/agents/ranking.py (Line 77)
  Function: RankingAgent._score_job()
  Problem:
    Line 77: `if s and s in desc_lower or s in title_lower:`
    In Python, `and` takes precedence over `or`. This is parsed as:

  Impact:
    If `s` is an empty string `""`, `(s and (s in desc_lower))` is False.

    An empty skill in the profile matches every single job.

7. DATA MODEL, PERSISTENCE & DEDUPLICATION AUDIT
================================================================================
- Primary Key: `id` is currently random UUID per search. Must become a deterministic 
  hash of `canonical_url` or `(source, source_job_id)`.
- Unique Constraints: Need unique index on `url` (or canonical URL hash) to 
  enable `ON CONFLICT DO NOTHING` / `DO UPDATE`.
- Date Column: `posted_date` is currently `String(100)`. Should have a companion 
  `posted_at` `DateTime(timezone=True)` column.
- Deduplication: Intra-batch deduplication works well in memory via company 
  normalization and token Jaccard similarity, but cross-search database-level 
  deduplication is absent.
- Repost Tracking: `repost_detector` records URLs in memory/DB, but lacks an 
  automatic expiration policy for closed positions.

================================================================================
8. FILTERING SYSTEM & LOGIC OPERATOR DEFECTS
================================================================================
- Multi-skill filtering uses strict AND in frontend (`every(tok => fullText.includes(tok))`). 
  If a user enters 4 skills, all 4 must appear. This is correct for specific 
  searches, but should offer a configurable threshold (e.g. at least 2 of 4).
- Empty filters on frontend correctly pass all jobs.
- Backend date filtering has the critical silent bypass bug (BUG-CRIT-002).
- Location filter defaults to "Remote" on backend if missing (BUG-MED-001).

================================================================================
9. JOB POSTED-DATE & FRESHNESS DEFECTS
================================================================================
- Relative dates ("3 hours ago", "2 days ago") parse to "N/A" and then return 
  True for freshness, letting old jobs pass (BUG-HIGH-002).
- Zero-results date filter drops the filter and returns ancient jobs (BUG-CRIT-002).
- Timezone handling: Uses UTC with a 1.5-day future leeway to accommodate 
  international timezone differences (acceptable design).

================================================================================
10. EXPERIENCE & SENIORITY EXTRACTION DEFECTS
================================================================================
- `min(found_min_years)` picks secondary tool requirements (e.g. "1 year Docker" 
  in a 7-year senior job) and classifies the job as Entry-Level (BUG-HIGH-003).
- Default fallback assigns 2 years (Mid-Level) whenever no digits are found, 
  mislabeling fresher and unquantified listings.
- Seniority keywords in title (`Senior`, `Lead`, `Principal`, `Staff`) must 
  always override description number parsing.

- Ranking agent assigns 100% location fit to any job in India for any Indian city 
  query (BUG-CRIT-001).

- Location helper contains excellent metro definitions for Pune, Bangalore, Mumbai,

14. 4-PILLAR RELEVANCE & SCORING DEFECTS
================================================================================
- Current formula: 35% Role + 30% Skills + 20% Experience + 15% Location.
- Due to the location bug (100%), skill default (75%), and generic role match (80%), 
  an irrelevant Bangalore role gets an 80.5% match score for an AI Engineer in Pune search.
